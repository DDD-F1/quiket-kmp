## Android 로그인 기록

초기 시도에서는 Android 원본 앱에서 테스트 계정 이메일로 `/api/v1/auth/login` 요청은 정상 전송됐지만, 서버가 아래처럼 `401 AUTH_INVALID_CREDENTIALS`를 반환했다.

| 항목 | 값 |
| --- | --- |
| HTTP status | `401` |
| code | `AUTH_INVALID_CREDENTIALS` |
| message | `이메일 또는 비밀번호가 올바르지 않습니다.` |
| failedLoginCount | `2` |
| remainingAttempts | `3` |

비밀번호 입력 길이 문제를 한 번 확인했다. 첫 시도는 비밀번호 필드가 13글자로 잡혔고, 이후 필드를 완전히 비운 뒤 12글자로 재입력했지만 서버는 동일하게 `AUTH_INVALID_CREDENTIALS`를 반환했다. 남은 시도 횟수 보호를 위해 추가 로그인 시도는 중단한다.

이후 동일 계정으로 다시 확인했을 때, 비밀번호 필드를 완전히 비운 뒤 `ja2hoon.test`를 12글자로 입력하고 키보드를 내린 상태에서 로그인 버튼을 눌러 정상 로그인됐다.

| 항목 | 값 |
| --- | --- |
| HTTP status | `200` |
| code | `AUTH_LOGIN_SUCCESS` |
| message | `로그인이 완료되었습니다.` |
| 후속 API | `/home` 200, `/subjects?page=0&size=50` 200 |

## 정적 분석 판정

| 영역 | 판정 | 근거 |
| --- | --- | --- |
| 인증/세션 | 대응됨 | CMP 루트에서 저장 세션을 읽고 `withRefreshedSession`으로 갱신한다. 갱신 실패 시 세션을 지우고 로그인 화면으로 보낸다. 이메일 로그인, 카카오 로그인, 회원가입, 비밀번호 재설정 화면이 모두 존재한다. |
| 세션 refresh 동시성 | 대응 강화 | Android `AuthTokenAuthenticator`는 refresh lock으로 동시 401에서 중복 refresh를 막고, invalid refresh token일 때만 토큰을 지운다. CMP도 `Mutex`로 refresh를 직렬화하고, 다른 요청이 이미 갱신한 토큰이 있으면 최신 세션으로 바로 재시도한다. refresh token이 401로 거절될 때만 세션 만료로 처리하고, 일반 네트워크 실패는 세션을 보존한 채 네트워크 오류로 전달한다. |
| 카카오 이메일 optional | 대응됨 | CMP `AuthUser.email`, `AuthTokenUser.email`, MyPage profile email이 nullable로 선언되어 있어 카카오 이메일 미제공 계정 파싱 실패 위험은 낮다. |
| 회원가입 플로우 | 대응됨 | Android와 CMP 모두 이메일 중복 확인을 첫 단계에서 수행하고, 약관 제출 시 `auth/signup`을 호출한 뒤 인증번호 화면으로 이동한다. 인증번호 화면은 재전송, 타이머 만료, 6자리 확인, 성공 시 토큰 저장 흐름을 갖는다. |
| 회원가입 약관 | 대응됨 | Android와 CMP 모두 서비스 이용 약관/개인정보 수집 및 이용만 필수이고 마케팅은 선택이다. 상세 화면에서 `확인 및 동의하기`를 누르면 해당 필수 항목이 체크된다. CMP 상세 제목/본문 분리도 Android와 동일하게 raw 첫 줄 제목 방식으로 보정했고, 약관 원문 diff도 동일하다. |
| 마이페이지 API | 대응됨 | Android `MyPageApi`의 프로필/닉네임/이메일 변경/비밀번호 변경/탈퇴/알림/FCM/문의 엔드포인트가 CMP `MyPageClient`에도 모두 구현되어 있다. |
| 마이페이지 계정 설정 | 대응됨 | Android와 CMP 모두 프로필의 `providers`에 `local`이 있을 때만 비밀번호 변경과 탈퇴 비밀번호 입력을 요구한다. 닉네임/이메일/비밀번호 변경, 회원 탈퇴 성공 후 로그아웃 흐름도 대응된다. |
| 마이페이지 알림/문의 | 대응됨 | 알림 설정은 양쪽 모두 activity/update/review 토글을 optimistic update하고 실패 시 이전 값으로 되돌린다. 문의는 category/body/replyEmail을 전송하며 `appVersion/osVersion/deviceModel`은 양쪽 모두 현재 생성 시점에 채우지 않는다. |

| 홈/시험/즐겨찾기 정렬 | 대응됨 | Android와 CMP 모두 즐겨찾기 과목을 먼저 정렬하고, D-Day 표기는 `D-N`, `D-Day`, `D+N` 규칙을 사용한다. 시험 일정 등록 제한 5개와 등록된 과목 비활성 처리도 대응된다. |
| 알림/FCM 토큰 | 공통 후순위 | 양쪽 모두 알림 설정 조회/저장 API와 `my/fcm-token` API 선언은 있다. 다만 실제 Firebase/APNs 토큰 수집 및 자동 등록 흐름은 Android dev와 CMP 모두 현재 코드에서 확인되지 않는다. CMP만의 누락은 아니다. |
| API endpoint surface | 대응됨 | Android `dev`의 인증, 홈, 과목/챕터/파트, 업로드, 퀴즈 생성/풀이/결과, 기록, 오답노트, 마이페이지 운영 엔드포인트는 CMP client에 대응된다. `feature:sample`의 `pokemon` 테스트 API는 비교 범위에서 제외한다. |

| 퀴즈 시작 타이머 | 대응됨 | Android와 CMP 모두 플레이 방식 변경만으로는 타이머 입력 모달을 열지 않고, `직접 입력` 선택 시에만 모달을 연다. iOS 실기에서도 `한번에 풀기` 선택 시 자동 모달 미노출 확인. |
| 퀴즈 시작 타이머 전달 | 대응됨 | Android와 CMP 모두 `한번에 풀기` 상태에서 직접 입력을 선택하면 전체 타이머(`Total`) 모드로 열리고, 적용한 초/분 값을 `timerSeconds`로 변환해 풀이 시작 config에 전달한다. |

## 우선순위 높은 검증 상태

1. S1/S2/S3는 API E2E와 Android/iOS UI 전용 실기 QA 모두 통과했다. 최종 생성 요청 직전까지 확인했고, 서버 데이터 추가를 피하려고 UI 실기에서는 `퀴즈 만들기` 버튼을 누르지 않았다.
2. 홈 화면은 정보 구조, 상단 로고/가이드/알림 아이콘, 튜토리얼 하이라이트 안내 방식까지 맞췄고, 하단 카드 밀도도 Android dev 홈에 더 가깝게 보강했다. 최신 홈 카드 보강분은 Gradle Android/iOS Kotlin 컴파일, Android 패키징, Xcode iOS Simulator 빌드, iOS 실기 스크린샷까지 확인했다.
